# AVORA ADMIN PANEL — COMPLETE IMPLEMENTATION PLAN

Mục tiêu: Xây dựng Admin Panel chuyên nghiệp cho Avora với RBAC + Permission + Branch-based Access, bảo mật toàn bộ Admin API ở Backend và giao diện responsive Desktop/Mobile.

## 1. ROLE & PERMISSION

Roles hiện tại:

- ADMIN: Toàn quyền hệ thống, xem tất cả chi nhánh hoặc từng chi nhánh, quản lý Users/Roles/Branches, Orders, Products, Categories, Promotions, Settings.
- MANAGER: Chỉ quản lý branch được gán qua `User.branchId`, không được xem branch khác hoặc `ALL`.
- CHEF: Chỉ hoạt động trong branch được gán, chủ yếu xem Orders, Order Details và cập nhật trạng thái liên quan đến bếp.
- USER: Không được truy cập Admin Panel/Admin API.

Thiết kế Permission theo:

`Role → Permissions → API/UI`

Permissions có thể gồm:

`dashboard.view`, `reports.view`, `users.view`, `users.update`, `orders.view`, `orders.update`, `orders.update_status`, `products.view`, `products.create`, `products.update`, `products.delete`, `categories.view`, `categories.create`, `categories.update`, `categories.delete`, `promotions.view`, `promotions.create`, `promotions.update`, `promotions.delete`, `settings.view`, `settings.update`.

ADMIN có toàn bộ permissions. MANAGER/CHEF chỉ có permissions phù hợp.

Frontend chỉ dùng Permission để điều khiển UI; Backend luôn phải kiểm tra lại Permission và Role.

## 2. BACKEND SECURITY

Kiến trúc:

`JWT → JwtAuthGuard → RolesGuard → Permission Guard/Policy → BranchAccessPolicy → Controller → Service → Prisma`

- `JwtAuthGuard`: xác thực JWT.
- `RolesGuard`: kiểm tra Role.
- `Permission Guard/Policy`: kiểm tra Permission.
- `BranchAccessPolicy`: kiểm soát phạm vi dữ liệu theo branch.

Branch rules:

- ADMIN + `ALL` → xem toàn hệ thống.
- ADMIN + branch cụ thể → chỉ xem branch đó.
- MANAGER → luôn bị giới hạn bởi `user.branchId`.
- CHEF → luôn bị giới hạn bởi `user.branchId`.
- USER → không được gọi Admin API.

Không bao giờ tin `branchId` từ Frontend. Nếu Manager/Chef gửi `?branchId=OTHER_BRANCH`, Backend phải bỏ qua/ghi đè bằng `user.branchId`.

Tạo `BranchAccessPolicy` dùng chung cho toàn bộ Admin Services, không copy logic branch filtering ở từng Controller.

## 5. USER MANAGEMENT

Route:

`/admin/users`

Không dùng `/admin/roles` làm trang quản lý chính vì trang này thực chất quản lý User + Role + Branch.

Features:

- Search theo Name/Email/Phone.
- Pagination.
- Role Badge.
- Branch Badge.
- Status.
- Manage User.

API:

`GET /api/admin/users`

`GET /api/admin/users/:id`

`PATCH /api/admin/users/:id/role`

Payload:

`{ role: 'MANAGER', branchId: 'abc' }`

Rules:

- MANAGER → bắt buộc `branchId`.
- CHEF → bắt buộc `branchId`.
- ADMIN → branch có thể NULL.
- USER → branch có thể NULL.
- Chỉ ADMIN được thay đổi Role/Branch.

Backend phải validate toàn bộ, không chỉ Frontend.

## 26. IMPLEMENTATION RULES

- Không phá code hiện tại.
- Không đổi API đang hoạt động nếu không cần.
- Không thay đổi Prisma Schema tùy tiện.
- Kiểm tra Schema trước khi viết Prisma query.
- Backend Security phải làm trước Frontend UI.
- Không tin Role/Permission/Branch từ Frontend.
- Không duplicate Branch filtering logic.
- Tái sử dụng Guard/Policy/DTO/Components.
- TypeScript type-safe.
- Hạn chế `any`.
- Không tạo file trùng chức năng.
- Không tạo code thừa.
- Sau mỗi Phase phải test trước khi sang Phase tiếp theo.
- Nếu phát hiện vấn đề trong Schema hiện tại, báo rõ nguyên nhân và đề xuất thay đổi trước khi migration.
